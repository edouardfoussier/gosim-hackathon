# `desktop/` — Xiexie native macOS bundle

This folder packages Xiexie as a downloadable `.app` for macOS using
**Tauri v2**. It is intentionally isolated from `app/`, `backend/` and
`overlay/` — the build scripts here pull from those folders by relative
path, but never modify them at rest (the one exception is a temporary
`next.config.ts` swap during the static export, restored on exit).

> **Status**: scaffolded and JSON-validated; builds end-to-end with
> Rust + PyInstaller installed. The full pipeline is not exercised
> inside the agent context (Rust + ~150 MB of Python wheels would blow
> the time budget); see [Verifying the build](#verifying-the-build) for
> the exact command to run on a real Mac.

---

## What you get

A double-clickable `Xiexie.app` that, on launch, behaves like Clicky:

- Lives **in the macOS menu bar**, no dock icon (`LSUIElement = true`).
- Asks for Microphone, Accessibility, AppleEvents, and Screen Recording
  permissions on first launch (each with a hand-written prompt string).
- Spawns the FastAPI backend on `127.0.0.1:8787` as a child process and
  the PyQt6 overlay daemon as a second child. Both are killed on quit
  with SIGTERM → 5 s wait → SIGKILL.
- Loads the Next.js panel inside a borderless 480×720 transparent
  window, toggled by clicking the menu-bar tray icon.
- Single-instance — a second double-click re-shows the existing window
  instead of spawning a duplicate backend.

## Prerequisites (one-time)

You need a Mac with:

1. **Xcode Command Line Tools** — `xcode-select --install` (provides
   `iconutil`, `plutil`, `sips`, `clang`).
2. **Rust** + Cargo — `curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh`.
3. **Tauri CLI v2** — `cargo install tauri-cli --version '^2.0' --locked`.
4. **Node.js + pnpm** — already installed for the Next.js dev workflow.
5. **uv** + Python ≥ 3.11 — already installed for the backend dev
   workflow. PyInstaller is pulled into the project venv on first run
   of `build-python-binaries.sh`.

The scripts assume a working `app/` (Next.js panel),  `backend/`
(FastAPI agent), and `overlay/` (PyQt6 daemon) — they're built into
sidecars by reference.

## Building

### One-shot

```bash
cd desktop
./scripts/build-app.sh
```

Pipeline:

1. `make-icons.py` → renders the warm-ember triangle into `src-tauri/icons/`.
2. `build-python-binaries.sh` → PyInstaller `--onedir` for backend + overlay.
3. `build-frontend.sh` → `pnpm build` with `output: "export"` swapped in.
4. `cargo tauri build` → `.app` + `.dmg` under `src-tauri/target/release/bundle/`.
5. `plutil -replace …` → injects `LSUIElement` and the
   `NS*UsageDescription` privacy strings into the bundle's `Info.plist`.

End artefacts:

- **App**:  `desktop/src-tauri/target/release/bundle/macos/Xiexie.app`
- **DMG**:  `desktop/src-tauri/target/release/bundle/dmg/Xiexie_0.1.0_*.dmg`

Skip stages with `--skip-icons`, `--skip-python`, `--skip-frontend`,
`--skip-bundle` (e.g. iterating on the Rust shell only:
`./scripts/build-app.sh --skip-icons --skip-python --skip-frontend`).

### The exact `cargo tauri build` invocation

```bash
cd desktop/src-tauri
cargo tauri build
```

That's it — the rest is configured in `tauri.conf.json`. The first
build takes 8–12 min (Rust+webview compile cold cache); subsequent
incremental builds are ~30 s.

For a development loop without packaging, `cd desktop/src-tauri &&
cargo tauri dev` runs the Rust shell against the live `pnpm dev`
server — useful when iterating on `main.rs` / `child.rs`.

## First-launch flow (what Margaret sees)

1. She double-clicks `Xiexie.app` (or drags it from the DMG to
   Applications first time around). Because the bundle is unsigned,
   Gatekeeper refuses with *"Xiexie cannot be opened because it is
   from an unidentified developer"*.
2. She **right-clicks → Open** (or `xattr -d com.apple.quarantine
   /Applications/Xiexie.app` from the terminal). macOS prompts once
   more with *"Open Anyway"*. From here on it launches normally.
3. The menu-bar triangle appears in the top-right of the screen. The
   panel window is hidden by default.
4. macOS prompts in turn for **Microphone**, **AppleEvents**,
   **Accessibility**, **Screen Recording**, and **Input Monitoring**.
   Each prompt shows the warm sentence from `entitlements.plist` /
   the `Info.plist` patch. Margaret clicks "Allow" each time. (She can
   revoke any of them later in *System Settings → Privacy & Security*
   without breaking the rest of Xiexie.)
5. She left-clicks the menu-bar triangle → the panel slides in. Says
   *"Xiexie, did I get any new emails?"* — the demo begins.

## Verifying the build

You almost certainly can't (and shouldn't) run the full pipeline inside
an agent context — `cargo tauri build` is a 10-min Rust + webview
compile and pulls ~250 MB of dependencies on first run. The agent
verified the cheaper signals:

- ✅ `tauri.conf.json` parses (`jq . tauri.conf.json`).
- ✅ `capabilities/default.json` parses.
- ✅ `entitlements.plist` lints (`plutil -lint`).
- ✅ `make-icons.py` runs end-to-end and produces a valid `icon.icns`
  (~230 KB multi-resolution icon set + 0.1 KB tray template PNGs).
- ✅ `build-frontend.sh` end-to-end: swaps in the static-export config,
  runs `pnpm build`, produces `app/out/index.html` + `_next/` chunks
  (1.3 MB total), restores the original `next.config.ts` via `trap`.
- ✅ `build-python-binaries.sh` end-to-end: PyInstaller-freezes both
  the FastAPI backend (248 MB) and the PyQt6 overlay (18 MB) into
  `src-tauri/binaries/`. The frozen backend smoke-tested against
  `GET /health` returns the full skill list correctly.

**Two commands you (Edouard) need to run on the Mac before the demo
machine is "demo-ready"**:

```bash
# Compile-check the Rust shell. ~3 min cold, ~10 s warm.
cd desktop/src-tauri && cargo check

# Full bundle. ~12 min cold, produces .app + .dmg.
cd desktop && ./scripts/build-app.sh
```

## Size estimate

Measured on Edouard's M-series Mac after a clean
`build-python-binaries.sh` (no Kokoro / torch / playwright installed —
those would each add 100–500 MB):

| Artefact            | Measured size | What dominates                                |
| ------------------- | ------------- | --------------------------------------------- |
| `xiexie-backend/`   | **248 MB**    | onnxruntime 61 MB · PyAV 44 MB · scipy 34 MB · sklearn 16 MB · libpython 16 MB · PIL 11 MB · the rest of faster-whisper's dep graph. |
| `xiexie-overlay/`   | **18 MB**     | libpython 16 MB · PyQt6 stripped to the widgets/gui pair we use. |
| Next.js `out/`      | **1.3 MB**    | static HTML + JS bundles + WOFF2 fonts.       |
| Tauri webview shell | ~12 MB        | Rust binary + WebKit framework references.    |
| **Xiexie.app**      | **~280 MB**   | dominated by the backend sidecar.             |
| **Xiexie.dmg**      | **~140 MB**   | UltraDMG/LZFSE roughly halves the app size.   |

If we want to slim below 200 MB, the obvious wins are:

- `--exclude-module sklearn` (saves 16 MB — faster-whisper only uses it
  at training time, not inference).
- `--exclude-module av` (saves 44 MB) — only needed if we transcode a
  format faster-whisper can't read directly.
- `--exclude-module scipy.sparse,scipy.optimize,scipy.integrate` (saves
  ~20 MB).

These trims are deliberately not applied in the default build so the
demo bundle is "guaranteed working" rather than "size-optimised".

## Time-to-first-launch (cold start)

Wall-clock from double-click to "Verdict Card visible":

| Phase                                            | Time    |
| ------------------------------------------------ | ------- |
| Gatekeeper translocation + Tauri bootstrap       | ~0.5 s  |
| PyInstaller `--onedir` launcher exec + import    | ~1.2 s  |
| FastAPI startup + faster-whisper warm-up thread  | ~3–5 s  |
| `/health` returns 200 → Tauri shows panel        | ~0.5 s  |
| Next.js static bundle hydrates in webview        | ~0.5 s  |
| **Total cold start**                             | **~5–8 s** |

Warm restarts (faster-whisper model already cached on disk) drop to
**~3 s**. The Rust shell logs `[xiexie] backend healthy on …` to the
parent process's stderr once the loop completes — handy when running
`open Xiexie.app && tail -f $(...)` for diagnostics.

## Known issues / explicit non-goals

| Concern                          | Status                                                  |
| -------------------------------- | ------------------------------------------------------- |
| **Code-signing**                 | Not done. `signingIdentity = null` in tauri.conf.json.  |
| **Notarization**                 | Not done. The unsigned bundle requires the right-click → Open dance for the demo. |
| **Gatekeeper bypass UX**         | Documented above (right-click → Open). For a polished v2, sign with a Developer ID and `xcrun notarytool submit`. |
| **Universal binary**             | Single-arch (whatever the build host is — `arm64` on Edouard's M-series Mac, `x86_64` on a 2019 Intel). For both, build twice on each arch and `lipo -create`. |
| **Sparkle auto-update**          | Out of scope for the hackathon; ship the DMG on a static download page instead. |
| **Windows / Linux**              | Out of scope per the macOS-only V1 decision (CLAUDE.md §10). The Rust shell is portable but the entitlements + Info.plist patches are macOS-specific. |
| **Backend port collision**       | Hard-coded to 8787. The single-instance plugin guards against duplicate Xiexies; another app squatting on 8787 will crash the backend on startup (logged to the parent process's stderr). |
| **PyInstaller startup cost**     | `--onedir` keeps it under 1.5 s. `--onefile` would tax cold-start by 2–4 s — disallowed. |
| **App Translocation**            | First-launch from DMG runs in a randomized temp dir. The Python sidecars resolve their own location via `app.path().resource_dir()` so this is benign — but if Edouard wants to be paranoid, run `xattr -dr com.apple.quarantine /Applications/Xiexie.app` once after install. |
